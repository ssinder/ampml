# 第三方验收操作手册

面向承担验收审计的第三方人员。本手册说明如何独立复现并验证本项目声称的模型性能指标。

文档版本：2026-10-19　|　对应项目状态：下游全链路可复现

## 一、验收目标与范围

### 1.1 本次验收验证什么

| 验收项 | 具体内容 |
|--------|---------|
| **准确率声称** | 主推模型 Gradient Boosting 在独立测试集上准确率 **0.8646**，超过 80% 验收阈值 |
| **指标可复现性** | 六个模型、30 项指标的复算值与交付记录完全一致 |
| **数据完整性** | 测试集规模、类别分布、样本可溯源性 |
| **环境合规性** | 依赖版本与锁定清单一致 |

### 1.2 本次验收不验证什么

明确边界，避免验收歧义：

- ❌ **不验证**训练过程是否泄露测试集信息（此项可通过代码审查完成，见第五章）
- ❌ **不验证**从原始生物数据库到本数据集的完整重建过程（存在已记录的不可复现环节，见第六章）
- ❌ **不验证**模型对全新肽段的泛化能力（需提供独立外部数据集）
- ❌ **不验证**生物学合理性（预测正确不代表机制正确）

## 三、执行复现

### 3.1 一键执行（推荐）

```bash
bash run_all.sh
```

该命令按序执行 8 个阶段：环境自检 → 数据预处理 → 特征选择 → 模型训练 → CV 曲线 → 图表 → SHAP → 验收审计。

**预期耗时**（macOS M 系列实测，全流程 **12 分 12 秒**）：

| 阶段 | 内容 | 耗时 |
|------|------|------|
| check | 环境自检 | < 10 秒 |
| 01 | 数据预处理与划分 | 约 10 秒 |
| 02 | 特征选择（5 种方法竞赛） | **约 8 分钟**（最耗时） |
| 03 | 六模型训练 + 5 折 CV | 约 3 分钟 |
| 03b | CV 曲线数据 | 约 20 秒 |
| 04b | 图表生成 | 约 15 秒 |
| 05 | SHAP 分析 | 约 30 秒 |
| 99 | 五层验收审计 | < 10 秒 |

### 3.2 分阶段执行

```bash
bash run_all.sh --list              # 查看所有阶段
bash run_all.sh --from 02           # 从特征选择开始
bash run_all.sh --only 99           # 只跑验收审计
bash run_all.sh --skip-check        # 跳过环境自检
bash run_all.sh --clean              # 清空产物从零重跑
```

### 3.3 单独执行某脚本

```bash
./venv/bin/python src/03_model_training_cv.py
```

所有脚本均已改为基于 `src/config.py` 推导绝对路径，**可从任意工作目录执行**。

## 四、验收判定

### 4.1 核心判据：执行审计脚本

```bash
./venv/bin/python src/99_verify_test_metrics.py
```

该脚本执行**五层递进审计**，任何一层不通过即判定验收失败。

| 层 | 审计内容 | 通过标准 |
|----|---------|---------|
| **L1** | 用混淆矩阵四格数**手算**各项指标，与 sklearn 结果对拍 | 差异 < 1e-6 |
| **L2** | 数据溯源：测试集规模 384、类别分布 185/199、特征数 300、样本 ID 映射 2557 条唯一 | 全部符合 |
| **L3** | 记录 6 个模型 pkl 的 MD5 指纹 | 文件存在且可加载 |
| **L4** | 复算指标 vs `model_comparison_data.csv` 记录值 | 30/30 项差异 < 1e-6 |
| **L5** | 准确率是否 ≥ 验收阈值（默认 80%） | 至少主推模型达标 |

**预期输出末尾**：

```
审计结论汇总
======================================================================
  L1 手算交叉验证   : 通过
  L2 数据溯源       : 通过
  L3 模型指纹       : 已记录 6 个
  L4 指标比对       : 30/30 项一致
  L5 达标判定       : 全部达标
----------------------------------------------------------------------
  最终结论: 五层审计全部通过：手算一致、数据溯源完整、指标完全对得上、全部模型达标
======================================================================
```

**退出码**：0 = 通过，1 = 未通过（可用于自动化判定）。

### 4.2 准确率声称核对

打开 `results/VERIFICATION_SUMMARY.md`，核对下表：

| 模型 | 准确率 | F1 | ROC-AUC | 达标 |
|------|--------|-----|---------|------|
| **Gradient Boosting**（主推） | **0.8646** | 0.8706 | 0.9432 | ✅ |
| Voting Ensemble | 0.8646 | 0.8700 | 0.9369 | ✅ |
| Random Forest | 0.8464 | 0.8491 | 0.9322 | ✅ |
| SVM | 0.8438 | 0.8477 | 0.9132 | ✅ |
| XGBoost | 0.8438 | 0.8500 | 0.9354 | ✅ |
| Logistic Regression | 0.8203 | 0.8288 | 0.9049 | ✅ |

**验收阈值 80%：六个模型全部达标**，主推模型超出阈值 6.46 个百分点。

### 4.3 指标口径说明（重要）

项目存在**两套指标口径**，不可混用：

| 口径 | 数值范围 | 文件 | 用途 |
|------|---------|------|------|
| **独立测试集** | 0.82 ~ 0.86 | `model_comparison_data.csv` | **验收依据** |
| 训练集 5 折 CV | 0.86 ~ 0.94 | `cv_results_summary.csv` | 辅助参考，**不作验收依据** |

CV 指标系统性偏高（LR 在 CV 上 0.9385 最好，但在测试集上 0.8203 最差），
说明其泛化能力最弱，**交叉验证分数不可作为模型选择或验收依据**。

对外报告准确率时**必须使用测试集口径**。

### 4.4 模型文件指纹核对

审计报告 `results/verification_report.json` 的 `model_files` 字段记录了各模型的 MD5。
第三方可独立计算并比对：

```bash
md5 -q results/models/gradient_boosting_cv_model.pkl
```

**作用**：证明本次审计所验证的对象，与交付时的模型文件为同一份（防止交付后替换模型）。

## 五、代码审查要点（防泄漏验证）

本节供具备代码审查能力的人员参考。**关键事实**：

### 5.1 超参搜索未使用测试集

`src/03_model_training_cv.py` 中：

```python
random_search.fit(X_train, y_train)     # 仅用训练集
```

验证集与测试集虽被读取，但**仅用于打印形状**，全程不参与训练或选模。
因此不存在利用测试集调参的行为。

### 5.2 特征选择未使用测试集

`src/02_feature_selection.py` 中，特征筛选方法竞赛仅在训练集内部做交叉验证，
`test_data.csv` 仅在最后做列裁剪，不参与特征选择决策。

### 5.3 数据划分方式

```python
train_test_split(X, y, test_size=0.3, stratify=y, random_state=42)
train_test_split(X_temp, y_temp, test_size=0.5, stratify=y_temp, random_state=42)
```

分层抽样，随机种子固定为 42。**可复现性已实测**：重跑得出完全相同的 1789/384/384 划分与 861/928、185/199、185/199 分布。

## 六、已知限制与声明边界

诚实披露以下事项。第三方应据此判断是否接受验收，或要求补充说明。

### 6.1 上游序列构建不可复现（最高优先级）

**事实**：从 UniProt / DRAMP 等原始数据库到本数据集的构建过程，存在以下断点：

| 断点 | 具体问题 |
|------|---------|
| MMseqs2 聚类参数缺失 | identity / coverage 阈值全库无记录，代表序列无法重生成 |
| 部分源数据遗失 | L1 的 5 个原始数据库导出文件中至少 3 个不存在 |
| 无检索日期与版本 | 原始数据查询未记录日期与库版本 |
| 手工步骤未留存脚本 | 去重 + 长度≤60 筛选步骤为手工操作 |

**影响范围**：`rawdata/all_features_combined_standard.csv` **可校验不可重建**。
其 MD5 可验证文件完整性，但无法从原始数据库重新生成同一份文件。

**建议验收表述**：将 `rawdata/` 视为**数据交付物**而非**可再生数据**。

### 6.2 跨类别标签冲突

**事实**：6 条氨基酸序列同时出现在 L0（非抗菌肽）与 L1（抗菌肽）两类中。
另有 L0 中 13 条序列与某 L1 序列共享 12 个连续氨基酸。

**成因**：L0 与 L1 来自两套独立构建流程，合并时未做交集去重。

**影响**：随机划分训练/测试集时，同源肽可能被拆到两侧，使评估结果偏乐观。

### 6.3 阴性样本语义偏差

**事实**：L0 实际是 UniProt 中 `reviewed:true AND length:[1 TO 60]` 查询结果的
全蛋白 60aa 片段（ATP 合成酶亚基、核糖体蛋白、膜蛋白等），而非独立采集的「非抗菌肽」。

**判定逻辑**：否定式启发判断（GO 术语 8 项黑名单 + 关键词 18 项黑名单 + 细胞外定位加分），
未检索 Pfam / InterPro 家族结构域。

**影响**：L0 与 L1 的序列分布存在系统性差异，可能构成准确率偏高的另一个来源。

### 6.4 上游代码缺陷（不影响本次交付数值）

`ampmodel/` 下存在若干已记录的代码问题（路径硬编码、多版本脚本并存、部分脚本在当前数据上无法运行）。
详见 `docs/REPRODUCIBILITY.md` 第四节。

**说明**：这些缺陷**不影响**已交付的 4921 维特征文件与下游模型的数值，
因为特征文件已固定且 MD5 可校验。

### 6.5 已知的数值漂移

重跑 `03_model_training_cv.py` 时，AUC 类指标（ROC-AUC / PR-AUC）可能出现 ≤ 3.7e-06 的漂移，
集中于 Logistic Regression。

**成因**：`roc_auc_score` 数值积分的浮点求和顺序对并行 BLAS 线程调度敏感，非代码缺陷。
所有阈值类指标（accuracy / precision / recall / F1）差异为 **0**。

**处置**：若需完全消除，可设 `OMP_NUM_THREADS=1` 强制单线程执行。

## 八、常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 自检报「依赖包缺失」 | 未用指定解释器安装 | `python3 -m venv venv && ./venv/bin/pip install -r requirements.txt` |
| 自检报「MD5 不符」 | 原始文件传输损坏 | 重新获取原始文件，勿继续验收 |
| 特征选择阶段极慢 | 正常，5 种方法 × 5 折 CV | 约 400 秒，属预期 |
| 审计脚本报「样本ID映射缺失」 | 未跑 `01` 脚本 | `bash run_all.sh --from 01` |
| 审计脚本报文件缺失 | 未执行完整流程 | `bash run_all.sh` |
| 指标与文档差 1e-06 量级 | AUC 浮点积分漂移 | 见 6.5，非缺陷 |
| 安装依赖网络超时 | 网络受限 | 配置代理后重试 |
